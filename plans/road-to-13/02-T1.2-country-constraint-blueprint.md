## DISEÑO — trigger per-row (barato, fail-closed)
Un cluster es `(cluster_run_id, canonical_ulid)` + miembros `entity_ulid`. Invariante: todo miembro
comparte country con su canonical. Trigger BEFORE INSERT/UPDATE en entity_cluster que compara el
country del miembro vs el del canonical (ambos en `entity`); si difieren → RAISE. Idéntico para
vehicle_cluster (vía `vehicle.country_code` / canonical_vehicle_ulid). Per-row → O(1), sin coste de
constraint cross-row.

## SQL BORRADOR (entity_cluster; [NO-VERIFICADO] — afinar con `\d entity_cluster` real)
```sql
-- 0071_entity_cluster_country_proof.sql  [BORRADOR — NO aplicar sin dry-run :5434]
CREATE OR REPLACE FUNCTION cardeep_entity_cluster_single_country() RETURNS trigger
LANGUAGE plpgsql AS $$
DECLARE c_member text; c_canon text;
BEGIN
  SELECT country_code INTO c_member FROM entity WHERE entity_ulid = NEW.entity_ulid;
  SELECT country_code INTO c_canon  FROM entity WHERE entity_ulid = NEW.canonical_ulid;
  IF c_member IS DISTINCT FROM c_canon THEN
    RAISE EXCEPTION 'entity_cluster row spans countries: member % (%) vs canonical % (%) [run %]',
      NEW.entity_ulid, c_member, NEW.canonical_ulid, c_canon, NEW.cluster_run_id
      USING ERRCODE = 'restrict_violation';
  END IF;
  RETURN NEW;
END $$;
DROP TRIGGER IF EXISTS trg_entity_cluster_country ON entity_cluster;
CREATE TRIGGER trg_entity_cluster_country
  BEFORE INSERT OR UPDATE ON entity_cluster
  FOR EACH ROW EXECUTE FUNCTION cardeep_entity_cluster_single_country();
-- idem vehicle_cluster con vehicle.country_code + canonical_vehicle_ulid.
-- Rollback: DROP TRIGGER ...; DROP FUNCTION ...
```
Nota de perf: el trigger hace 2 SELECT por fila insertada. En un re-cluster masivo (cientos de miles
de filas con execute_values) esto puede pesar — alternativa a evaluar con DB: una validación SET-based
post-insert dentro de la misma txn (`SELECT 1 FROM entity_cluster ec JOIN entity em ... JOIN entity ec2
... WHERE em.country_code <> ec2.country_code` → si devuelve filas, RAISE y rollback) en vez de trigger
per-row. Decidir con medición en :5434.

## CRITERIO 13/10 (cuándo el invariante es MECÁNICO)
Un INSERT directo (sin pasar por el código Python) de un cluster cross-country es RECHAZADO POR LA DB;
`v_country_proof_violations` queda estructuralmente en 0 por construcción (no por disciplina). Entonces
"country-proof" deja de ser una vista-detectora y pasa a ser una imposibilidad mecánica — los 3
cinturones (keys + aserción-código + constraint-DB) en capas.
