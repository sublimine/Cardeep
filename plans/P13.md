## 2. Arsenal SOTA (investigado este 2026-06-20)

- **DSLR (Database Snapshot, Local Restore) — patron PostgreSQL TEMPLATE** _(libreria · MIT · v0.6.0 (2025-07-09), 171 stars, 10 releases; activo 2025. El VALOR es el patron template-DB (nativo Postgres 16, ya en uso), no la dependencia.)_
    - Resuelve el corazon del problema: sembrar una DB realista por test/run SIN pagar el coste de pg_restore. Usa CREATE DATABASE ... TEMPLATE (clonado copy-on-write de Postgres): ~8x mas rapido en snapshot y ~3x en restore que pg_dump/pg_restore. Es exactamente el mecanismo que necesita el job de comportamiento del CI (crear un template seeded una vez, restaurar antes de cada modulo de tests). MIT permite portar el patron (3 comandos SQL) al runner del CI; el caveat 'dev only' se evita NO usandolo sobre la DB de produccion sino sobre la DB efimera de CI.
    - <https://github.com/mixxorz/DSLR>
- **diff_cover (Bachmann1234)** _(libreria · Apache-2.0 · ~835 stars, releases activas en 2025-2026 (v10.x), usado por tox; mantenido.)_
    - Permite imponer un gate de cobertura INCREMENTAL (solo lineas del diff vs main) en vez de exigir 80% global de golpe sobre un repo de ~1110 tests sin cobertura medida — un gate global rojo seria green-washing inverso. diff-cover compara coverage.xml contra `git diff origin/main` y falla con --fail-under si las lineas nuevas/tocadas no estan cubiertas. Es el patron correcto para subir cobertura monotonicamente sin bloquear todo el repo el primer dia.
    - <https://github.com/Bachmann1234/diff_cover>
- **LiteLLM (proxy/gateway self-hosted)** _(servicio · MIT (OSS; enterprise tier separado e innecesario) · ~40k stars, produccion, releases continuas 2025-2026; Docker self-host con volumen persistente.)_
    - Es el cost-router que falta (baseline: 'sin cost-router'). Un unico endpoint OpenAI-compatible delante de Ollama (qwen2.5:3b local, ya en .env) Y de APIs de pago, con routing por complejidad, fallbacks, spend-tracking y budgets como cambio de config. Encaja con la doctrina coste-cero: la capa masiva (clasificar/parsear/dedup) va a Ollama local $0 y solo escala a API de pago bajo autorizacion del owner, con el gasto MEDIDO. 'nginx para LLMs': 4ms overhead a cambio de auth+budget+fallback+cost-tracking.
    - <https://github.com/BerriAI/litellm>
- **SOPS + age** _(tecnica · MPL-2.0 (sops) / BSD-3 (age) · sops bajo CNCF, ampliamente adoptado; age estable y mantenido 2025-2026.)_

Para los pocos secretos ESTATICOS de cardeep (DSN prod, DECODO_PROXY, CAPSOLVER_KEY, LiteLLM master key) es la opcion de menor coste operativo; age es el backend moderno (vs PGP). ## 3. Arquitectura objetivo (10/10 institucional)

Diseno 10/10 en cuatro planos, todos coste-cero hasta que el owner autorice el VPS.

PLANO 1 — REPRODUCIBILIDAD (imagen + compose por perfiles). Dockerfile multi-stage para la app: base python:3.11-slim + capa R (r-base + paquetes Rcapture/dga/LCMCR) porque estimators_r.py invoca Rscript; pip install requirements*.txt. docker-compose.yml extendido con PROFILES: `core` (pg, ya existe), `app` (api uvicorn :8090 + scheduler BlockingScheduler), `llm` (litellm proxy + opcional ollama), `obs` (prometheus + grafana + node-exporter + opencost-exporter). Local arranca solo `core`; produccion arranca todo. .dockerignore y healthchecks por servicio. Resultado: una maquina limpia hace `docker compose --profile app --profile obs up -d` y tiene el sistema completo.

PLANO 2 — CI QUE SI CORRE LOS TESTS (el gap central). Nuevo job `behavioral-suite` en ci.yml: (a) arranca postgres:16 service, (b) migra 0001->0040, (c) SIEMBRA una DB plantilla `cardeep_template` con un fixture determinista y comiteado (countries/ES sample + filas minimas por tabla que satisfagan los 42 skipif) — el seed vive en tests/fixtures/seed.sql versionado, NO un dump de 500k filas, (d) `CREATE DATABASE cardeep TEMPLATE cardeep_template` (patron DSLR) antes de cada grupo de tests para aislamiento, (e) corre `pytest -m "not slow" --cov=services --cov=pipeline --cov-report=xml`, (f) `diff-cover coverage.xml --compare-branch origin/main --fail-under=80` (gate INCREMENTAL). Se introduce conftest.py con la fixture de DB y registro de markers (unit/integration/slow) para eliminar los PytestUnknownMarkWarning. El `--collect-only` actual se queda como gate de import barato en el job rapido; el nuevo job es el gate de comportamiento.

PLANO 3 — SECRETS + IaC. secrets.enc.yaml cifrado con SOPS+age (DSN prod, DECODO_PROXY, CAPSOLVER_KEY, LITELLM_MASTER_KEY, grafana admin); .sops.yaml con la age public key; clave privada en GitHub Actions secret + en el VPS. IaC: un solo Terraform module (provider hetzner/hcloud) que declara el servidor, el volumen de datos pg, el firewall (solo 22/443, pg jamas publico — consistente con docker-compose linea 24), y cloud-init que instala Docker + clona repo + descifra secrets + `docker compose up`. Reversible: `terraform destroy` borra todo; el estado vive en backend remoto cifrado.

PLANO 4 — COST-ROUTING + OBSERVABILIDAD DE COSTE. LiteLLM como unico punto LLM: config.yaml ruta tareas-baratas->ollama/qwen2.5:3b ($0) y escalado->API de pago SOLO si CARDEEP autoriza (budget cap por dia). El codigo deja de hablar con OLLAMA_URL directo y habla con LiteLLM (OpenAI-compatible), ganando spend-tracking gratis. Observabilidad: Prometheus scrapea api/scheduler (metricas §9: ban-rate por domain), node-exporter (CPU/RAM/disco del VPS), opencost-exporter y el endpoint de spend de LiteLLM; Grafana con 3 dashboards: Salud (ban-rate/silencio por fuente), Coste (EUR VPS/mes, EUR/proxy, tokens-EUR por vector de descubrimiento), Cobertura del censo (el certificado §2 N̂+IC servido por la API). 

CONTRATOS: el seed fixture es la fuente de verdad de "datos minimos para que el comportamiento sea testeable"; toda nueva feature que añada un skipif debe añadir filas al seed. El gate de despliegue (Fase 6) es binario: behavioral-suite verde + diff-cover>=80 + certificado de cobertura emitido + `terraform plan` limpio.

## 6. Beyond-SOTA (la ambicion: mas alla del estado del arte)

El estado del arte 2026 trata seeded-snapshot CI y certificacion de cobertura como problemas separados. El movimiento beyond-SOTA de cardeep es fusionarlos en un GATE DE DESPLIEGUE DEMOSTRABLE: el mismo pipeline que prueba que el codigo no regresiona (behavioral-suite sobre DB template-seeded) emite, en la misma corrida, el CERTIFICADO DE COBERTURA NACIONAL §2 (N̂+IC por provincia×tipo via captura-recaptura) como un ARTEFACTO FIRMADO Y VERSIONADO adjunto al release. Es decir: produccion no se despliega porque 'los tests pasan', sino porque el sistema puede DEMOSTRAR matematicamente — con intervalo de confianza, reproducible desde el repo en una maquina limpia — que indexa el % declarado del censo de Espana. Ningun pipeline de scraping conocido acopla 'CI verde' a 'prueba estadistica de completitud del dominio servido' como condicion de release atomica. Ademas el cost-router LLM-local-first hace que el coste marginal de re-ejecutar la prueba completa de exhaustividad sea ~$0, permitiendo emitir el certificado en cada push sin gasto — convirtiendo la demostracion de completitud en un invariante continuo, no un evento puntual.

## 7. Riesgos

- El seed fixture (P13.2) puede derivar respecto al esquema real (43 migraciones) y dar falso verde si no se mantiene; mitigacion: regla 'todo skipif nuevo añade fila al seed' + un test que verifica que el seed cubre todas las tablas con al menos 1 fila.
- La imagen Docker con R+Rtools+Splink puede ser pesada y lenta de construir en CI; mitigacion: capa R cacheada + multi-stage; mantener el job rapido (collect-only+import) separado del pesado.
- diff-cover --fail-under sobre lineas del diff puede bloquear PRs de codigo dificil-de-testear (subprocess R, conectores con red); mitigacion: gate incremental no global + marcador de exclusion justificado caso a caso.
- terraform apply y la creacion del VPS son IRREVERSIBLES y con coste real: jamas ejecutar sin instruccion literal del owner (mandato Fase 6: solo tras verificacion local total + certificado emitido).
- LiteLLM como single point: si cae, toda la capa LLM cae; mitigacion: fallback ollama-directo configurado y healthcheck con restart unless-stopped.
- Si el certificado de cobertura §2 (P2.3) no esta listo, el dashboard de Cobertura y el gate beyond-SOTA quedan en stub honesto, no fabricado — declarar el hueco, no maquillarlo.
